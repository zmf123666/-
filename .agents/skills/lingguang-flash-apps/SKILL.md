# 灵光闪应用开发与发布

灵光闪应用是使用 React + TypeScript 开发的 HTML5 应用，可运行在移动端 App WebView、PC 浏览器或移动浏览器的 iframe 中，并通过 `lingguang.*` API 使用宿主提供的服务端和客户端增强能力。本技能指导官方项目初始化、已有项目迁移、质量检查、源码打包、预览发布和正式发布。

应用代码必须使用外部提供的官方 React 脚手架。禁止把 React 代码库或真实访问令牌复制到本技能中。

## 渐进式路由

先把本 `SKILL.md` 所在目录记为 `SKILL_DIR`，再根据用户当前目标选择流程文档。每次只完整读取当前阶段需要的文档，禁止在任务开始时一次读取全部 `references/`：

- 新建闪应用或继续开发由官方脚手架创建的项目：读取 [references/create-project.md](references/create-project.md)。
- 迁移或改造已有项目：先读取 [references/migrate-project.md](references/migrate-project.md)。迁移目标尚未创建时，再按总 Skill 路由读取 `create-project.md`。
- 构建、质检、打包、预览发布或正式发布：读取 [references/build-and-release.md](references/build-and-release.md)。
- 首次实际调用发布 API，或需要查询、排查接口响应：在发布流程文档基础上，再读取 [references/deploy-api.md](references/deploy-api.md)。

同一任务推进到下一阶段时，届时再读取下一阶段文档；不要提前加载。若用户同时明确要求多个阶段，按执行顺序逐阶段读取和完成。

## 执行方式

由 Agent 主动完成当前阶段内的下载、检查、修改和验证，不要求用户代为运行命令或手工检查源码。遇到系统软件安装、敏感授权或重大产品取舍时，再按对应流程暂停并征得用户确认。

## 本地预览打开方式

需要打开本地 Preview Host 验证应用时：

1. 启动本地服务并确认 Preview Host URL 可访问后，优先使用当前 Agent 的内置浏览器打开预览并完成检查。
2. 页面可访问且运行时已连接时，如仅出现 Vite HMR WebSocket 连接错误，先刷新一次；该错误本身不视为内置浏览器打开失败。
3. 仅在没有内置浏览器、内置浏览器明确打开失败，或服务已就绪但刷新后仍无法访问时，才使用系统默认外部浏览器作为兜底。禁止默认或并行拉起 Chrome 等外部浏览器。
4. 禁止通过 Vite `server.open`、`open`、`xdg-open`、`start` 或直接启动浏览器进程绕过上述顺序。
5. 两种浏览器都不可用时，输出 Preview Host URL，并明确说明未完成浏览器侧验证。
6. 交付时说明实际使用的浏览器。云端预览二维码仍由用户使用灵光 App 扫码验证，不属于本地浏览器流程。

## 通用开发约束

1. 开始操作项目前，先确认用户目标、源项目目录（如有）和输出目录，并完整读取项目适用的 `AGENTS.md`。
2. 只按当前功能需要读取项目内的 `docs/API_*.md`，并以这些文档和当前脚手架代码为事实来源。
3. 只使用脚手架 `package.json` 已声明的依赖；安装 Node.js 依赖时使用 `https://registry.npmmirror.com`。
4. 保护平台维护的 `src/main.tsx`，不得用业务入口覆盖它。
5. 在项目根目录维护 `manifest.json`。以 `plugins/manifest-utils.ts` 和 `plugins/vite-plugin-validate-manifest.ts` 为字段、封面格式和路径规则的事实来源。
6. 禁止把访问令牌、Cookie、环境密钥或其他敏感信息写入源码、压缩包、提交记录、命令参数或诊断日志。
7. 发现原因明确、影响范围小且不改变用户需求或产品行为的简单问题时，可以自行修复并告知用户。涉及功能取舍、产品行为变化、数据风险、新增依赖或扩大任务范围时，先给出影响和建议，取得用户确认后再修改。

## 跨阶段发布门禁

1. 发布前必须完成发布流程文档中的全部强制质检；任何检查未执行、无法执行或失败时，禁止继续打包和发布。
2. 必须先预览发布并交付结果，明确等待用户确认预览无误后，才能正式发布。
3. 正式发布必须复用通过质检和用户确认的同一源码包及已保存的应用身份。源码、依赖、配置、资源或源码包变化后，必须重新质检、重新预览并再次等待确认。
4. 预览和正式发布均须查询到 `PASS` 才算成功；不得只根据 HTTP 200 判断成功。
5. 令牌未配置或未确认时，必须暂停发布并先完成安全配置。

## 阶段交付

- 新建：交付结构完整、符合脚手架规范的 React 源码项目。
- 迁移：默认交付隔离的新目录，保留原项目不被覆盖。
- 预览：交付应用名称、应用 ID、版本号和二维码，并说明预览链接 10 分钟后失效；等待用户确认。
- 正式发布：交付正式版本信息和二维码，并说明可在灵光 App 或网页版「我的创作」查看。
